# Rank Culture — Security Audit

**Date of assessment:** 11 November 2026 (IST) · **Assessor:** Claude (AI), for Nakul Chaturvedi · **Commit audited:** `d8adca6` on `production-hardening` (live site runs `7a1f7fd`; the difference is migration 0017 and its tests)

## 1. Executive summary

**Overall risk rating: Medium.**

The platform's foundations are sound. Scores are computed only on the server, answer keys never reach the browser, every table has row-level security, privileged database functions pin their search path and use no dynamic SQL, bot sign-ups are blocked by an enforced CAPTCHA, and the browser is locked down by a strict hash-based Content-Security-Policy. No account-takeover, data-leak, injection or remote-code-execution flaw was found.

The material risks are about **rank integrity**, which is the product's core promise to employers:

- **Fixed in code, not yet applied to the live database:** a single account could farm a top skill-leaderboard spot by re-answering one practice question (High), and spare accounts could farm Arena rating through private events or paired public matches (Medium). Migration `0017_rank_integrity.sql` closes all three and adds a review queue for inhumanly fast answering. It is tested (11 new attack tests) and needs your approval to apply.
- **Open by design:** tournament questions are identical for every player for a 30-day window, and a phone pointed at the screen can ask an AI. These need product changes (question pools, per-question timers, a live verified round); see `security/SECURITY-REMEDIATION-PLAN.md` and the Fair Play Plan doc.
- **Manual provider settings:** password change does not require the current password within 24 hours of login; backups and restore are unverified on the Free plan; MFA on the admin accounts (Supabase, Vercel, GitHub, Google Cloud, GoDaddy, Resend) was not verified.

**Production deployment recommendation:** the live site is fit to stay up for the pilot. Apply migration 0017 before any public "verified rank" claim. Do not market ranks as cheat-proof until the High-severity open items in the remediation plan are done.

## 2. Scope and limitations

**In scope:** source repository `nakulchaturvediwrk/rank-culture` (branch `production-hardening`), the Supabase project `vxzbiytdjcyaqupgxjzx` (database schema, functions, grants, policies, cron jobs, auth settings), the Vercel project `rank-culture` (headers, routing, deployments), and the live site https://rankculture.in.

**How testing was done:** there is no staging environment. Active tests ran on (a) a full replica of every migration in PGlite (`supabase/tests`), (b) Vercel preview builds, and (c) the production database **only inside transactions that were rolled back**, with synthetic users. Live-site checks were read-only. No denial-of-service, credential stuffing, password spraying or destructive tests were run. No real user data was read; the database has 2 accounts.

**Not assessed:** the founder mailbox setup (ImprovMX, Brevo), GoDaddy DNS account security, MFA status of the admin accounts, Supabase backup/restore (not visible on Free plan, not tested), Vercel team access list, and anything outside the repository. Supabase Auth internals (token signing, refresh rotation) are trusted as provider controls.

## 4. Threat model (summary)

| Actor | Goal | Main controls | Residual |
| --- | --- | --- | --- |
| Anonymous visitor | Read private data, call game functions, spam | No table grants for `anon`; only 9 safe RPCs; rate limits on contact/feedback | Contact form global cap can be exhausted (L-4) |
| Bot | Mass sign-up, scripted play | Turnstile enforced; auth rate limits (30 sign-ins / 5 min / IP); speed flags (R4) | Scripted answering by a human-created account (detected, not blocked) |
| Malicious player | Inflate own rank | Server-side scoring and timing; one attempt per tournament; R1–R3 fixes | Same tournament questions for all; phone-AI (H-2, H-3) |
| Player with spare accounts | Farm rating, scout questions | R2, R3 fixes; email confirmation | Throwaway emails (M-3) |
| Compromised session | Take over account | Re-login to delete account; secure email change; reauth code for password change after 24 h | Password change within 24 h of login (M-1) |
| Compromised admin account | Everything | Provider MFA (not verified) | M-5 |
| Malicious feedback text | Steer the weekly AI pipeline | `_check_batch` validation, human review link, independent re-answer check; runbook now says feedback is untrusted | Auto-publish when not held (M-2) |
| Dependency compromise | Malicious build | Lockfile, single runtime dependency (`@supabase/supabase-js`), pinned esbuild | No CI or SRI (L-7, I-1) |

## 6. Controls verified (evidence)

- **Authorization:** 104 automated database security checks pass (`supabase/tests/security.test.mjs`), covering anonymous lock-out, cross-user isolation, grants, rate limits, deletion. Re-confirmed live (rolled back): a second user cannot read or change another user's entries, applications, ratings or private rooms; anonymous visitors get `permission denied` on all private tables and game functions.
- **Scoring integrity:** answer keys are in a table with no grants; tournament prompts unlock only after the player's own timer starts; submissions after time + 2 min grace are rejected; one entry per tournament; battle answers are server-timed with a 750 ms network grace; duplicate, early, late and out-of-range answers are rejected (live rolled-back test).
- **Injection:** no `EXECUTE`/dynamic SQL in any public function; all SECURITY DEFINER functions set `search_path = ''`; every database value written into HTML passes `esc()`; the remaining unescaped interpolations are numbers, constants or clipboard text; `?next=` redirects are restricted to `name.html?query` on the same site.
- **Browser:** CSP `script-src 'self'` + 48 SHA-256 hashes (no `unsafe-inline`, no `unsafe-eval`), `frame-ancestors 'none'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`; HSTS 2 years with preload; `X-Frame-Options: DENY`; `nosniff`; `Referrer-Policy: strict-origin-when-cross-origin`; Permissions-Policy denies camera, mic, location, payment, USB. Confirmed on the live response.
- **Auth:** CAPTCHA enforced server-side (a password request without a token returns `captcha_failed`); rate limits 30 sign-ups/sign-ins per 5 min per IP, 30 code checks per 5 min per IP, 150 token refreshes per 5 min per IP, 30 emails/h; email confirmation on; secure email change on; secure password change on; redirect allow-list only `https://rankculture.in/**` and `https://rank-culture.vercel.app/**`; PKCE; account deletion needs a login within 10 minutes.
- **Secrets:** full Git-history pattern scan (Stripe, Resend, JWT, GitHub, Google, private keys, Supabase secret keys): none found. No source maps shipped.
- **Dependencies:** `npm audit` 0 vulnerabilities after the esbuild upgrade (root and test packages).

## 7. Residual risks

Even after every fix: a determined player with a second device and an AI can still score well online; the defence is the live verified round, not the web page. Throwaway email accounts remain possible until phone OTP or ID checks are added. Provider-side controls (Supabase Auth, Vercel, Cloudflare) are trusted, not tested. Nothing here proves the system is "unhackable"; it shows which realistic attacks were tried and what stopped them.
